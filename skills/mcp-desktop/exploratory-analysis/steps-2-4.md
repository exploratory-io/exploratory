# 手順 2〜4（手順 1 の HTML のレポートを保存した後に読む）

手順 1 で保存した HTML のレポートを見本にして、次の順に進める。

2. Exploratory でどう作るかの計画を書く。計画の各行は、次の 4 つの規則で加工を決める。
   (1) 分岐は、行数・1 行の単位・表の構造が変わる加工（集計、ワイド型からロング型へ・ロング型からワイド型への変換、結合、行の絞り込み、重複除去）のときだけ作る。列を足すだけ（mutate、日付から年月、区分や点数の列、因子の順序）は分岐せず、元のデータにステップを足す。同じ元表から同じ形の集計を複数の図で使うときは、分岐は 1 本にして図を共有する（図 1 枚に分岐 1 本を作らない）。
   (2) R の 1 つの処理は、Exploratory の 1 つのコマンドに置き換える。group_by+summarise は summarize_group、filter は filter、mutate は mutate、pivot_longer/wider は pivot_longer/pivot_wider、arrange は arrange、top_n は top_n、left_join は join。同じ設定を複数の列に当てる処理は、列を配列で受ける 1 ステップ（mutate_multiple、set_factor_levels、recode、bin の columns）。
   (3) exp_custom（カスタム R コマンド）は、対応するコマンドが無い処理（例: 行を期間の月数ぶんに展開する unnest、再帰的な計算）だけに使い、1 ステップに 1 処理。式は 表 %>% 式 の形で実行されるので、`d <- .`・`df %>%`・`{ }` で始めず、`mutate(...)`・`filter(...)` のように動詞から書く。使うときは計画の行に「コマンドが無い理由」を 1 句で書く。
   (4) 回帰・相関・クラスタリングなど、アナリティクスのテンプレートがある計算はアナリティクスで作り、その出力を save_result_as_dataframe で表にしてから図にする（R で係数や距離を計算し直さない）。
   規則の詳細（NA の扱い、失敗時の戻し方）は、最初の create_wrangling_step の前に 1 回だけ ../exploratory-wrangling/common/wrangling-common.md の「分岐」の節を読む。
   HTML のレポートの各図・各分析・各加工を、Exploratory のどの道具（create_wrangling_step、create_chart、create_analytics、create_note）で作るかを、Markdown の表にする。HTML の図（画像・グラフ）と表の 1 つにつき 1 行で、1 つも抜かさない。各行には、HTML の図表の名前、R で使った手法・対象の行・欠損の扱い・重み・計算式、Exploratory でどの経路（下の a〜d）で作るか、使う道具と設定を書く。チャートの種類・設定、アナリティクスのテンプレート、加工のコマンドは、list_chart_settings・list_analytics_templates・get_wrangling_command などで実在を確かめて書く。計画は HTML のレポートと同じ作業フォルダに、`<題名>_Exploratory作成計画.md` の名前で Markdown のファイルとして保存し、本文に元の HTML のファイル名を書く。返答にも示す。計画を書き終えて保存するまで、Exploratory で作り始めない（確認のための読み取りの道具は使ってよい）。作った結果とのずれは、手順 4 の表に書く。 計画の最後の行には、全部の図表を HTML のレポートと同じ構成と順番で 1 つのノート（create_note）にまとめる行を必ず入れる。
   経路 a（分析で作る区分の列。クラスタ、グループ分けなど）: Exploratory でも同じ設定（変数・標準化・乱数の種・試行回数・欠損の扱い）でアナリティクスを作り、その「データ」の出力を save_result_as_dataframe でデータとして保存し、そのデータからチャートを作る。各区分の人数と中心を HTML と比べ、区分の番号が入れ替わっていれば、名前の付け替えで HTML にそろえる。
   経路 b（集計した表から描く図）: R でした計算を、Exploratory のデータ加工のステップ（フィルタ、計算を作成、集計、ワイド型からロング型へ・ロング型からワイド型への変換、結合など）に 1 つずつ置き換えて集計表を作り、チャートで描く。分岐を作るかどうかは、上の規則 (1) で決める（図 1 枚ごとには作らない）。計画には、R の処理のどの部分をどのステップで作るかを書く。対応するステップがない処理だけ、規則 (3) に従ってカスタム R コマンドにし、計画の行に理由を書く。チャートで描けない形だけ、カスタムチャート（R）で作る。
   経路 c（層ごとに分けた図）: ブランチでフィルタや加工をして、チャートを作る。
   経路 d（上のどれでもなく、標準の道具で足りるもの）: そのまま create_chart・create_analytics で作る。
3. 計画に沿って Exploratory で作る。Exploratory でできることは、Exploratory（create_wrangling_step、create_chart、create_analytics、create_note）で全部作る。Exploratory でできないものだけ、ステップのカスタム R コマンド（exp_custom）かカスタムチャート（R）で作る。R の値や文を、図表の代わりにノートの本文へ直接書かない。 作った図表を HTML のレポートと同じ構成と順番で 1 つのノートにまとめるまでが、この段の作業である。ノートを作らずに手順 4 へ進まない。 カスタム R コマンドは、対応する UI のステップがない処理だけに使い、複数の処理を 1 つのステップにまとめない。確認は手順 4 で全部行う。
4. 計画とのずれと、HTML のレポートとのずれを確かめて報告する。作ったものが計画のとおりか、HTML のレポートの図・値・構成と合っているかを確かめ、ずれがあれば理由を調べて、直せるものは直す。直せないものは、何がどうずれているかと理由を伝える。実行できなかった項目があれば、何が未実行かを明記する。 確かめた結果は、HTML のレポートの図ごとに「Exploratory で作ったもの・計画とのずれ・値のずれ・形のずれ・理由」を並べた表にして返答に書く。値は人数・割合・係数などの主要な数、形は図の種類・軸・系列・並び順で、両方を各行に書く。 表は作成時の引数から埋めず、保存後に get_chart_data・get_analytics・get_note などで実物を読み直して比べる。「未確認」と書いてよいのは、読み直しの道具が失敗したときだけで、その場合は理由を書いてもう一度読み直す。「未確認」が残っている間は、完了と報告しない。点検のフックがオフのときは、検証役のサブエージェントを立てず、自分で読み直して表を埋める。 照合で見つけたずれのうち、Exploratory の設定や加工で直せるもの（並び順、軸の向きや使う指標、割合と件数の違い、図に表示する数値、手法や検定の種類の違い、抜けた図・列）は、報告の前に直す。直したら、その図をもう一度読み直して照合し直し、照合表には直した後の結果を書く。直せないものだけを、直せない理由と一緒に照合表に残す。照合表に「未確認」の行があるうちは報告せず、読み直しの道具でもう一度読んでから報告する。 進め方は次の順にする。(a) 照合表を書く。値と形に加えて見た目も比べる。Exploratory で作ったチャートは、1 枚ごとに open_chart → get_chart_image → get_chart_data の順で 1 応答にまとめて送る。open_chart を省かない。見た画像を、HTML のレポートの同じ図と、色の付け方・強調・凡例・軸と項目の名前・数値ラベル・並び・文字の切れや重なり・読みやすさを比べる（道具の説明にある「複数のチャートでは一つずつ見ない」は、この照合の段には当てはめない）。アナリティクスの図は画像の道具で見られないので、get_analytics で出力を読み、値と形（図の種類・軸・並び・表示する項目）で照合する。これは「未確認」に数えない。チャートは一枚も飛ばさずに画像で見る。照合表に「見た目のずれ」の列を足す。照合表の最後にノートの行を足し、HTML のレポートと見出しの構成・図表の順番・本文の結論を比べる。各行に「直せる・直せない」を付ける。(b) 直せる行を一つずつ、update_chart・update_analytics・加工のステップなどで直し、直した図を読み直し、画像ももう一度見る。(c) 照合表を書き直し、直した行は直した後の値と形にする。(b) の直す操作を一度もせずに報告しない。「直せない」と書けるのは、list_chart_settings(marker=その図の種類) の返答に該当する設定が無いことを確かめ、照合表に「探した設定名」を書いたときだけ。軸・凡例・数値の見出しが、列名のまま（接頭辞付きなど）や集計の既定名（「行数」「合計」など）のままで、読み手に何の数かわかりにくいときは、表示名（displayName・xAxisTitle・yAxisTitle など）で、その数が何を表すかがわかる名前に変える。よく探し損ねる設定（名前の正は list_chart_settings の返答で、ここは探す場所の例）: 横向き = orientation: "horizontal"、値のラベル = yValueOnPlot: "on"、桁 = numDecimalDigits、% 表記 = yAxisNumberFormatting: "percentage"（横向きでも yAxis）、並び = sortTarget と sortOrder（意味順の軸は set_factor_levels の加工で順を決める）、強調 = highlightValues と axes.color に同じ列、凡例や軸の名前 = displayName / xAxisTitle / yAxisTitle。アナリティクスの出力は get_analytics_template の出力一覧で確かめる。R のレポートの誤りに気づいて直したときは、照合表のその行に「HTML を直した（理由）」と書き、直した HTML を再保存する。

ダッシュボードを頼まれたときも、同じ 4 つの順で進める。手順 1 では、R で計算とチャートを作り、ダッシュボードとして一画面に並べた HTML を作って保存する（見出し、主要な数値、チャートの配置まで、利用者がそのまま使える完成品のつもりで作る）。手順 2 の計画の最後の行は、全部のチャートを HTML と同じ配置と順番で 1 つのダッシュボード（create_dashboard）にまとめる行にする。手順 3 はダッシュボードにまとめるまでを作業とし、ノートは作らない。公開は利用者が明示したときだけ行う。
ダッシュボードで、Number チャート（主要な数値）は、ページ上部の Number 用の行に置く。列は 2〜3 本、各列のパネルは上から順に HTML の並びに合わせる。HTML で横向きのバーにした図は、バーの設定 orientation: "horizontal" で横向きにする。軸の項目名は、HTML と同じ短い表示名にする。
