# ダッシュボードを作るときの製品の使い方と、元の成果物の操作部・一覧・表の作り方

## ダッシュボード

Number チャート（主要な数値）は numberRow: true の行に置き、チャートの行より前に書く。元が数字の上に基準日の行や短い要約文を置いているときは、その文だけを入れた numberRow の行を Number の行の前に置く（ナンバー行は高さが決まった帯なので、そこに置く文は 2〜3 行まで。長い説明はチャートの行の text に回す）。Number 用の行では columns を使わない。columns を使うページでは numberRow を付けない（columns の前の行がナンバー行になる）。ダッシュボードではノートを作らない。公開は利用者が明示したときだけ行う。ページ名は「Page 1」のままにせず、内容がわかる名前にする。ダッシュボードはデータを更新して見返すものなので、題名・見出し・テキストに特定の年月や数値を書き込まない（例: 「10月・前年同月比」「2026年10月時点」ではなく「最新月・前年同月比」）。基準日を today() にしたときは、元に基準日の脚注があるときだけ「基準日: 今日」と書く（要約文が基準日を式で出しているなら足さない）。 元の数字カードの中にある小さな説明の文（「割引後の売上金額の合計」のような定義・注記）は、別の text パネルの行にしない。Number のチャートの description に入れ、ダッシュボードには出さない（元と形が変わることを報告に書く）。

text パネルの本文には R の値を埋め込める（`r 式`）。R のチャンクで作った変数は、そのパネルの中でしか使えない（別のパネルではそのパネルのチャンクで作り直す）。パラメーターは R の中でも @{名前} で参照する（例: y <- as.numeric("@{period}")）。素の名前（period や period_year）は R には無く、その行でチャンクが止まる。チャンクは、パラメーターのどの値でも止まらないように書く。「全期間」や空の値は as.numeric で NA になるので、if の条件は isTRUE(sp > 0) のように包み、NA を先に分ける。チャンクが途中で止まると、後ろの変数が作られず、本文の `r` が「オブジェクトがありません」になってダッシュボード全体が描けなくなる。正しい例（年のパラメーター period、値に「全期間」もある）: y <- suppressWarnings(as.numeric("@{period}")); cur <- if (is.na(y)) 売上データ else 売上データ[year(売上データ$注文日) == y, ]; prv <- if (is.na(y)) cur[0, ] else 売上データ[year(売上データ$注文日) == y - 1, ]; s <- sum(cur$売上); sp <- sum(prv$売上); delta <- if (isTRUE(sp > 0)) sprintf("前年比%+.1f%%", (s / sp - 1) * 100) else "前年との比較はありません"。本文で使う変数は、どの分かれ道でも必ず作る。データフレームはその R 名（list_data_frames の rName）を式にそのまま書いて参照する（例: `r format(nrow(売上データ), big.mark = ",")`）。get("名前") のように文字列で参照すると、データフレームが読み込まれず「オブジェクトがありません」になる。R 名に記号があってインラインの式に書けないときは、同じパネルに R のチャンク（```{r} の行、x <- nrow(`名前`) のように逆引用符で参照、``` の行）を置き、`r x` で埋め込む。元に数字の入った要約文（例: 「会員 1,250 人、うち今月の新規 48 人」）があるときは、この形で元と同じ位置の text パネルに元の文のまま作り、数字だけを式にする。R のチャンクで作った変数は、そのパネルの中だけで使える。別のパネルの文で使う値は、そのパネルのチャンクでもう一度作る。

ダッシュボードのチャート・アナリティクスのパネルは題を必ず出す（create_dashboard の panels.title。省くとチャート名。showTitle はテキスト・画像パネルにしか効かない）。図・表の見出しは panels.title に元の文言のまま渡し、text パネルに同じ見出しを重ねない。text パネルの行（その図の行のすぐ上。説明文が図の下にあるなら下）には、複数の図をまとめる節の見出しと、図・表ごとの説明文だけを置く。

## 元の成果物にある操作部・一覧・表の作り方

絞り込み（製品・期間などを選ぶ欄）はパラメータで作る。save_parameter で候補を持つパラメータを作り（「すべて」は複数選択 lov の useAllValuesAsDefaultValues）、絞り込む列を落とす集計より前に filter（conditions: [{column, operator: "in", parameter: 名前}]）を 1 回だけ置き（そこから分かれる分岐には重ねない）、create_dashboard の variables に渡す。新規・更新・追加の区分のように元が全製品の履歴から決める計算は、絞り込む前の全行で先に済ませ、その後に filter、表示用の集計の順に置く（先に絞ると他製品の契約が見えず区分が変わる）。単一選択を複数選択にするなど操作の形を変えたら報告に書く。

絞り込む列と、比較に使う日付の列は集計で落とさない。数字カード用に全指標を 1 行の表へまとめず、Number はチャートの集計（func）とチャートフィルタで作る。


元の一覧（表）は、同じ列・見出しの文言・行数・並び順で作る。行をまとめた一覧は集計テーブル（作り方・桁・単位は共通の手順書の加工の節）で、見出しは meas・rowh の displayName に元の文言で書く。行をまとめずにそのまま並べた一覧は、元の行の表に table を作り、表ごとに filters で絞る（分岐を作らない）。書式で作れない表記（「5 日遅れ」のような文言つきの値、年月だけの日付）だけ表示用の列を mutate で作り、元が右寄せなら tcol に align: "right" を付ける。table の並びは、並べる tcol の列に sortOrder と sortPriority（"1" から）を最初から両方付けて決め、arrange・select は足さない（出さない列で並べるときだけ arrange）。

元の表が製品の 1 つの出力で作れないとき（例: 項目ごとに寄与率・相関・係数・P 値・VIF が並ぶ表）は、分析の出力を save_result_as_dataframe で表にして join でまとめ、table で出す。係数・信頼区間・P 値の表も係数の出力を同じく表にし、filter・select（区間を 1 列にするなら mutate）のあと table で作る。ノート本文の手書きの表にしてよいのは、その値が Exploratory のどの出力にも無い列だけで、値の出どころを書く。

項目名に人数を添える（例: 「東京(n=120)」）ときは、mutate_group で区分ごとの件数の列を作り（groupBy に区分の列、window の func に count）、mutate で表示用の列（例: `paste0(地域, "(n=", 件数, ")")`）を作って軸に置く。

月別・年別などの切り替えは、元と同じく切り替わる図だけが変わる形をまず試す（粒度のパラメータを作り、mutate の式で @{パラメータ名} を参照した期間の列を図の軸にする）。それで作れないときは、粒度ごとにページを分ける（ページが 2 つ以上あるとタブになる）。分けたら操作の範囲と配置の変化を報告に書く。年末の有効数のような時点の値は、月末の値を足さず年の最後の時点で集計する。

ずらした窓での集計（移動合計・移動平均・累計）は、1 つの値ならチャートの表計算（yWindowFunc の rollsum など、窓の大きさは yWindowFuncSize）で作る。窓の中の合計どうしの比のように 2 つの値を組み合わせるときは、表計算では出ないので加工で作る。集計し、行の並びで数える式のときは時間の順に arrange し（欠けた期間があると行数が期間にならない）、mutate で `RcppRoll::roll_sum(x, n = 窓, align = "right", fill = NA)` の列を作って割る（RcppRoll は読み込まれないので `RcppRoll::` を付ける。通らなければ `cumsum(x) - dplyr::lag(cumsum(x), 窓, default = 0)`）。同じ図に 2 本の線を並べるなら line の axes.y に 2 列を配列で渡す。
直近 N 期間だけを見せるには、X が日付の図の settings に xPostFilterType: "relativeDates"、xPostFilterRelativeDateType（"month" など）、xPostFilterRelativeDateValueType: "last_n"（今日から。データの最新日からは "latest_n"）、xPostFilterRelativeDateVal: N を渡す（表示だけの制限で、加工で計算した値は変わらない）。全期間との切り替えは、日付 1 つの Date パラメータを save_parameter {"name": 名前, "type": "Date", "input": "field", "optionsType": "manual", "optionsDateValueType": "first_day_of_n_months_ago", "optionsDateNValue": N, "supportIgnore": true}（既定は N か月前の月初、空にすると全期間）で作り、その図の create_chart の filters に {"column": 日付の列, "operator": "greaterThanOrEqualTo", "parameter": 名前} を渡して（加工の filter ステップや分岐は足さない） create_dashboard の variables に渡す。optionsType を "predefined" にしない（predefined は「直近 7 日」などの決まった範囲の名前だけを持ち、日付 1 つや N か月前の既定値は入らない）。日付 1 つのパラメータに Quick Filter（within_date_range）は使えない。全期間の値を使う Number や表は、その前のステップを step に指定する。元の図が直近 N 期間だけを表示しているときは、切り替えが無くても上の相対日付の設定を必ず付ける（付けないと全期間が出る）。
